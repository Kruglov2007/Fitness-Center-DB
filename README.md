# 🏋️‍♂️ Fitness Center Management System (MS Access Database)

Проект представляет собой локальную реляционную базу данных на платформе **Microsoft Access**, разработанную для автоматизации работы фитнес-центра. Система позволяет вести учет клиентов, абонементов, сотрудников, расписания занятий, посещений, дополнительных услуг и инвентаря, а также формировать детальную бизнес-отчетность.

## 📊 Схема данных и Архитектура

База данных построена на основе связей «один-ко-многим» (`1:M`) с поддержкой целостности данных. Архитектура включает в себя следующие ключевые сущности:

*   **clients** (Клиенты): Персональные данные, контакты, даты регистрации.
*   **memberships** & **client_memberships** (Абонементы): Учет проданных тарифов, цен, дат начала и окончания действия.
*   **staff** (Сотрудники): Учет персонала клуба по ролям/должностям.
*   **room** (Залы): Физические помещения фитнес-центра и их вместимость.
*   **classes** & **class_registrations** (Занятия и Запись): Расписание тренировок, закрепление тренеров/залов и журнал записи клиентов.
*   **services** & **service_orders** (Дополнительные услуги): Учет продаж бара, массажа, персональных тренировок.
*   **check_ins** (Посещения): Контроль визитов (время входа/выхода) и занятых шкафчиков.
*   **equipment** (Оборудование): Инвентаризационный учет техники и тренажеров по залам с контролем их состояния.

## 📈 Реализованная отчетность (Reports)

Все отчеты спроектированы вручную в **режиме Конструктора (Design View)** с применением табличных макетов, выравнивания элементов и содержат динамические метаданные (текущая дата, время, нумерация страниц вида `Страница N из M`).

### 1. Простой отчет («Оборудование»)
*   **Назначение:** Инвентаризационная ведомость тренажеров и техники.
*   **Структура:** Компактный вывод списка оборудования (`id_equipment`, `equipment_name`, `purchase_date`, `status`) без избыточных пустых интервалов.

### 2. Отчет с группировкой и итогами («Итоги_Продаж»)
*   **Назначение:** Финансовый аудит продаж клубных карт.
*   **Группировка:** Данные распределены по типу абонементов (`name`).
*   **Вычисления:** 
    *   В области *Примечание группы* рассчитывается промежуточная выручка по конкретному абонементу через функцию `=Sum([price])`.
    *   В области *Примечание отчета* выводится глобальный финансовый результат фитнес-центра за все время.

### 3. Отчет по штату («Сотрудники»)
*   **Назначение:** Анализ кадрового состава и нагрузки.
*   **Группировка:** По должностным ролям сотрудников (`role`).
*   **Вычисления:** Автоматический подсчет количества сотрудников на конкретной должности (`=Count([id_staff])`) в примечании группы и вывод общего штата сотрудников в конце документа.

### 4. Финансовый отчет («Доходы_Услуги»)
*   **Назначение:** Аналитика продаж дополнительных услуг клуба.
*   **Реализация:** Построен на базе реляционного SQL-запроса, объединяющего таблицы `services` и `service_orders`. Рассчитывает общую выручку с продаж услуг.

### 5. Журнал посещаемости («Записи_на_Занятия»)
*   **Назначение:** Контроль загруженности групповых программ для тренеров и администрации.
*   **Группировка:** Связывает таблицы `classes`, `room`, `staff` и `class_registrations` для отображения списков клиентов, записанных на конкретные тренировки в определенные залы.

## 🛠️ Технологический стек

*   **СУБД:** Microsoft Access 2007–2024 (`.accdb`) / Access Runtime
*   **Язык запросов:** Access SQL (внутренние запросы на объединение `INNER JOIN`)
*   **Инструменты проектирования:** Конструктор форм, Конструктор отчетов, Построитель выражений MS Access

## 🚀 Как запустить проект

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com
   ```
2. Убедитесь, что на вашем компьютере установлен **Microsoft Access** (входит в состав MS Office Professional) или бесплатный **Access Runtime**.
3. Откройте файл `Database1.accdb`.
4. Для просмотра отчетов перейдите в левой навигационной панели в категорию **«Отчеты»** (Reports) и откройте любой из них двойным кликом (рекомендуется использовать *Режим предварительного просмотра* перед печатью).
